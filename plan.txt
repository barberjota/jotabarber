ARQUITECTURA Y ESPECIFICACIÓN TÉCNICA - SISTEMA DE GESTIÓN PARA PELUQUERÍA
================================================================================

1. RESUMEN DEL PROYECTO
--------------------------------------------------------------------------------
Desarrollo de una plataforma web integral para peluquería/barbería enfocada en:
- Portal de Clientes con Autenticación (Registro/Login):
    * Historial de citas y estado en tiempo real.
    * Sistema de fidelización por puntos y recompensas automáticas (ej. 5to corte con descuento/gratis).
    * Canje de puntos por productos (ceras, fijadores) o servicios.
- Gestión Administrativa Modular:
    * Agenda, barberos/estilistas, servicios, control de inventario de productos y ventas (POS).
    * Gestión y ajuste de reglas de puntos/fidelización y promociones.
- Identidad Visual / Estilo: Monocromático de alto contraste (Negro y Blanco / Minimalista & Dark Luxe).
- Stack Tecnológico: React + Prisma ORM + PostgreSQL (Supabase) + Despliegue en Render.

================================================================================
2. SISTEMA DE FIDELIZACIÓN, PUNTOS Y CLIENTE FRECUENTE
================================================================================

2.1. Reglas de Fidelización por Citas:
- Contador de Cortes/Servicios Completados:
    * El sistema registra cada cita con estado COMPLETED.
    * Regla del 5to Corte: Al agendar la 5ta cita (o al completarse la 4ta), el sistema aplica un
      descuento automático configurable (ej. 50% de descuento o corte gratis) en el resumen de reserva.
    * El contador se reinicia o se maneja por ciclos (Corte 5, 10, 15, etc.).

2.2. Sistema de Puntos Acumulables (Puntos de Fidelidad):
- Por cada monto gastado en servicios o productos (ej: 1 punto por cada $1 / 10 Bs gastados).
- Los puntos acumulados se visualizan en el perfil del cliente.
- Redención: Los clientes pueden usar sus puntos acumulados como descuento en citas o para canjear productos.

2.3. Autenticación y Perfil de Usuario:
- Roles en Base de Datos: CLIENT, STAFF (Barbero), ADMIN.
- Clientes: Registro con Email, Contraseña, Nombre y Teléfono.
- Beneficios del Cliente Autenticado:
    * Visualización de su tarjeta de fidelidad digital (Progreso: "Llevas 3/5 cortes para tu descuento").
    * Historial de citas pasadas y citas próximas con opción de reprogramar o cancelar.
    * Saldo de puntos y catálogo de recompensas canjeables.

5. MODELO DE BASE DE DATOS (ESQUEMA PRISMA / POSTGRESQL)
================================================================================

datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")
  directUrl = env("DIRECT_URL")
}

generator client {
  provider = "prisma-client-js"
}

enum Role {
  ADMIN
  STAFF
  CLIENT
}

enum AppointmentStatus {
  PENDING
  CONFIRMED
  COMPLETED
  CANCELLED
}

enum RewardType {
  FIFTH_HAIRCUT_DISCOUNT
  POINTS_REDEMPTION
}

model User {
  id              String           @id @default(uuid())
  email           String           @unique
  password        String
  name            String
  phone           String           @unique
  role            Role             @default(CLIENT)
  pointsBalance   Int              @default(0)       // Saldo de puntos acumulados
  completedCuts   Int              @default(0)       // Contador de cortes para el ciclo de 5 cortes
  appointments    Appointment[]
  sales           Sale[]
  loyaltyLogs     LoyaltyHistory[]
  createdAt       DateTime         @default(now())
  updatedAt       DateTime         @updatedAt
}

model Stylist {
  id           String             @id @default(uuid())
  name         String
  photoUrl     String?
  isActive     Boolean            @default(true)
  appointments Appointment[]
  schedules    StylistSchedule[]
  createdAt    DateTime           @default(now())
}

model StylistSchedule {
  id        String  @id @default(uuid())
  stylistId String
  dayOfWeek Int     // 0 = Domingo, 1 = Lunes, ..., 6 = Sábado
  startTime String  // Ej: "09:00"
  endTime   String  // Ej: "19:00"
  stylist   Stylist @relation(fields: [stylistId], references: [id], onDelete: Cascade)
}

model Service {
  id           String        @id @default(uuid())
  name         String
  description  String?
  durationMin  Int           // Duración en minutos (ej: 30, 45, 60)
  price        Decimal       @db.Decimal(10, 2)
  countsForFidelity Boolean  @default(true) // Si este servicio suma al ciclo del 5to corte
  isActive     Boolean       @default(true)
  appointments Appointment[]
}

model Product {
  id          String      @id @default(uuid())
  name        String
  description String?
  price       Decimal     @db.Decimal(10, 2)
  pointsCost  Int?        // Costo en puntos si se puede canjear
  stock       Int         @default(0)
  imageUrl    String?
  isActive    Boolean     @default(true)
  saleItems   SaleItem[]
}

model Appointment {
  id                 String            @id @default(uuid())
  userId             String            // Cliente registrado
  stylistId          String
  serviceId          String
  dateTime           DateTime
  endTime            DateTime
  status             AppointmentStatus @default(CONFIRMED)
  discountApplied    Decimal           @default(0.00) @db.Decimal(10, 2)
  isFifthCutPromo    Boolean           @default(false) // Indica si se aplicó el beneficio de cliente fiel
  notes              String?
  user               User              @relation(fields: [userId], references: [id])
  stylist            Stylist           @relation(fields: [stylistId], references: [id])
  service            Service           @relation(fields: [serviceId], references: [id])
  sale               Sale?
  createdAt          DateTime          @default(now())
  updatedAt          DateTime          @updatedAt
}

model LoyaltyHistory {
  id          String      @id @default(uuid())
  userId      String
  points      Int         // Positivo al ganar puntos, negativo al canjear
  reason      String      // Ej: "Cita completada", "Compra de cera fijadora", "Descuento 5to corte"
  rewardType  RewardType?
  user        User        @relation(fields: [userId], references: [id], onDelete: Cascade)
  createdAt   DateTime    @default(now())
}

model Sale {
  id            String       @id @default(uuid())
  userId        String?
  appointmentId String?      @unique
  subtotal      Decimal      @db.Decimal(10, 2)
  discount      Decimal      @default(0.00) @db.Decimal(10, 2)
  total         Decimal      @db.Decimal(10, 2)
  pointsAwarded Int          @default(0)
  pointsUsed    Int          @default(0)
  user          User?        @relation(fields: [userId], references: [id])
  appointment   Appointment? @relation(fields: [appointmentId], references: [id])
  items         SaleItem[]
  createdAt     DateTime     @default(now())
}

model SaleItem {
  id        String   @id @default(uuid())
  saleId    String
  productId String
  quantity  Int
  unitPrice Decimal  @db.Decimal(10, 2)
  sale      Sale     @relation(fields: [saleId], references: [id], onDelete: Cascade)
  product   Product  @relation(fields: [productId], references: [id])
}

6. LÓGICA DE DISPONIBILIDAD Y TURNOS (BACKEND)
================================================================================

Algoritmo de cálculo de horarios:
1. Entrada: stylistId, serviceId, date (YYYY-MM-DD).
2. Obtener duración del servicio desde la tabla Service (durationMin).
3. Obtener el horario de trabajo del estilista para el día de la semana correspondiente (StylistSchedule).
4. Obtener todas las citas existentes no canceladas del estilista para esa fecha.
5. Generar bloques de tiempo (ej. intervalos de 30 o 15 minutos) desde startTime hasta endTime.
6. Descartar bloques donde:
   (HoraSlot + DuraciónServicio) > HoraFinJornada
   O donde el intervalo [HoraSlot, HoraSlot + DuraciónServicio] se solape con cualquier cita existente.
7. Retornar al frontend la lista de slots disponibles en formato ["09:00", "09:30", "11:00", ...].

Lógica al Completar una Cita (Completar Cita -> COMPLETED):
1. Incrementar el contador `completedCuts` del cliente si el servicio aplica (`countsForFidelity = true`).
2. Si `completedCuts` llega a 5:
   * Activar bono/cupón automático para el próximo corte o registrar la recompensa en `LoyaltyHistory`.
   * Reiniciar contador a 0 o ciclar a múltiplos de 5.
3. Otorgar puntos calculados en base al monto final pagado.

8. PLAN DE DESPLIEGUE (RENDER + SUPABASE)
================================================================================

Paso 1: Configuración en Supabase
- Crear un nuevo proyecto en Supabase.
- Obtener DATABASE_URL (Transaction Pooler) y DIRECT_URL (Direct Connection).
- Ejecutar migraciones con Prisma (`npx prisma migrate deploy`).

Paso 2: Despliegue de Backend en Render
- Crear un Web Service conectado al repositorio GitHub.
- Configurar variables de entorno: DATABASE_URL, DIRECT_URL, JWT_SECRET, PORT, CORS_ORIGIN.
- Build Command: `npm install && npx prisma generate && npm run build`
- Start Command: `npm start`

Paso 3: Despliegue de Frontend en Render
- Crear un Static Site conectado al repositorio GitHub.
- Build Command: `npm install && npm run build`
- Publish Directory: `dist`
- Configurar variable: `VITE_API_URL` apuntando a la URL del backend en Render.
- Configurar Rewrite Rules para SPA (Redirigir /* a /index.html).
